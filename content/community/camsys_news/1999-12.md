{{begin-newsitem |time=1999-12-30T07:46:00Z |title=StarGraft News |author=King Arthur |site=Camsys |categories=Camsys}}
I've just completed adding support for Self-Exectuing Patches (which can include SECWADs, too if you select one). This ability will be added into the next version of StarGraft, which looks like it should be done sometime tomorrow if all goes well. The Self-Executing Patches will be at least 170kb in size, which will grow depending on whether you have a SECWAD or not, and the size of the patch file itself.

SEPatches will only support the versions of SC that the creator of the patch has support for. I.e. a copy of versions.dat will be tacked onto the end of the SEPatch for use in loading the patch. However that file will only be as up to date as the version the patch creator had. In this way I suppose you could do multiple versions, which would be especially helpful for SC/BW versions, which for the most part are incompatible with each other because of the drastic # of changes involved in the EXE.
{{end-newsitem}}

{{begin-newsitem |time=1999-12-20T17:44:00Z |title=TileEdit News Update. (not a release yet though) |author=Nossirahdrof |site=Camsys |categories=Camsys}}
Well, there's some good news and some bad news from the world of Tileset Editing. First, the bad news.

I have recently figured out (although I should have caught it earlier) that there is a limit on the amount of graphics that can be put into a Tileset. I won't go into great detail about why, mostly because the explanation would be long and probably more than most people would understand. So for now, the ability to import tiles is somewhat limiting. Which brings me to my next news bit, this time the good part. I have successfully completed the Exporting and Importing abilities of TileEdit. There are still a few minor bits and pieces to work out, but essentially it works.

So combining the bad news and the good news, we get the fact that Tiles can be imported to the Tileset, but once the limit is reached, that's it.

So, what shall be done? Well, in the next few days I'm going to try and create some kind of Tileset optimization to take away minitiles that have doubles or flipped doubles (probably the same technique Blizzard uses to reduce file size). This should help in lowering the size of the Tileset files once you've imported new graphics. Hopefully with this, the limit will be reached only in rare circumstances, but it will always be there.

So when can the next release be expected? Hopefully if all goes well, by Christmas I'll have a new version out, one way or another. If I find that the optimization will be more difficult than I am estimating, then I'll release a version without it, but hopefully, I'll get it put in so it'll be a much better release.
