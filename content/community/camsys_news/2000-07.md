{{begin-newsitem |time=2000-07-31T03:16:05Z |title=The new version sees the light of the day... |author=Gold Dragon |site=Camsys |categories=Camsys}}
It took more time than originally expected, but one thing for sure, it was worth it. ScAIEdit 3.1 is now publically released! With 26 changes over the previous version, you'll certainly want to download it if you're already using ScAIEdit 3.0. Since it's still a big file, I'll give you the download link right away so you can continue reading while downloading ;)

[ScAIEdit 3.1](https://web.archive.org/web/20000818043445/http://www.camsys.org/cgi/download.cgi?id=scaiedit31) (2.34 MB) - written by [Gold Dragon](mailto:GoldDragon@camsys.org)

I'd like to apologize for the lack of news from me these last days, especially on the progress of ScAIEdit 3.1. I've been quite silent for the past days/weeks, except on ICQ/#CamSys. I've been really busy during that time, and haven't been able to work much on ScAIEdit 3.1 until the last days. And when I started working heavily on it, I simply didn't want to post news because I thought it would be better to wait for the release, which took a bit longer than I expected. I still have a little number of unreplied e-mails and didn't write much on the feedbacks/forums, but know that I read every e-mail I receive and I also read the feedbacks, only that I can't always reply them in a short amount of time. But all in all, the 3.1 update is now released, so it should compensate ;)

On a side note, many have complained about the fact I didn't release the opcode name list. I haven't answered this yet, and I'll be doing right now : the list was not as useable as you might think. I didn't receive the complete opcode knowledge database, but an helpful list of the opcode names. It wasn't useable in its original form, so there was a lot of tweaking/testing necessary to convert them in the opcode database, and that's precisely why I decided to not release it before ScAIEdit 3.1. Also note that it was my own decision to share these good news with you before time. If I get too much of such reactions, I'll simply stop to tell you important progress news and wait until the product is released. I won't be doing it, but I'm only saying that getting this kind of reactions is a bit annoying. Thanks for those who reacted well ;)

Others have wondered how ScAIEdit 3.1 can export to MPQ files, and the answer is simple : ScAIEdit 3.1 generates a batch file executing [MPQ2k](https://web.archive.org/web/20000818043445/http://www.campaigncreations.com/starcraft/mpq2k/) to save the MPQ file. That means you'll need to install it in order to activate this feature. Then you'll only have to point to the location of MPQ2k in the ScAIEdit III options. As simple as that ;)

Script making should be now quite interesting, but it's now your turn to explore the new possibilities. I wish you good luck and feel free to ask any questions about ScAIEdit 3.1 and scripts. Feedback is very appreciated too :)

Until next update! :)
{{end-newsitem}}

{{begin-newsitem |time=2000-07-20T14:11:39Z |title=Windows Adventures part 3 |author=Gold Dragon |site=Camsys |categories=Camsys}}
**Important note:** If you don't want to read the whole post, at least read this paragraph. *I've lost all my e-mails that were received after July 13th and before July 19th.* If you sent your e-mail on this range of time, please [e-mail](mailto:GoldDragon@camsys.org) it again, else it will be considered as lost. Thanks for reading. For more details, read below :)

I think you've already guessed my computer has crashed another time. Seems to happen often, eh? :) This has not happened today though, but yesterday morning. At least now I know why, and it shouldn't happen again before a long time. I'll describe a bit later on this post. This time is similar to the previous one, NDD crashed the C: drive by correcting lost strings. That's why I've lost e-mails, as I described above, and since I had around 16 unreplied e-mails obtained in these days, it would be good to send them again :)

I said I know why my computer crashed all these times. Well it's quite simple : the FAT table of my C: drive was wrong since the beginning. Since I always took my backups to avoid reinstalling everything, these backups always had a wrong FAT table, because this error seems to have happened a long time ago. How comes I had a wrong FAT table when I could still use my computer? For those who don't know, there is 2 FAT tables on a partition, for security matters I think. The problem is, one of these 2 copies was corrupted, and when NDD wanted to correct the mistakes, it used the corrupted copy as well, screwing up the C: drive. I'm pretty sure it would have been the same with ScanDisk. At least, I'm happy it happened with C:, because if it would have happened with G: for example, it would have been less fun(G: is the drive for all my programmation stuff :). Although I backup my vital stuff often on my other computer AND my CD-RW backup disk, it would have obviously been a bit dated(of a week, for now).

So am I really unlucky? Not at all. All these crashes were linked together, and now that this is fixed, I shouldn't have the same problem for quite a while. I'm back with a completely clean system, once again, and I'm not sad with this. In fact, for strange reasons, msgsrv32, a core Windows module, always crashed at midnight on my last system. I've tried to figure out why, but it seems that Windows has gone really far this time :) I even set my clock to 23:59:30 and waited 30 seconds for it to crash, and it did! Funny, but annoying ;) At least it doesn't do that anymore, so I prefer having a clean system now :)

For those waiting anxiously at ScAIEdit 3.1 to be out, you may have wondered why I haven't given any news these last days, and what I've been doing. This is due to 2 things : first, I've been really busy for few days, which disallowed me to work on the update. I won't go on details with this, you don't really care about that ;) And second, I've got my new video card I was waiting for a long time :) For those wondering, it's an Asus AGPV3800-TNT2/32MB. It's true, this is not the state-of-the-art, but I'm quite satisfied with it and compared to my old Voodoo1 4MB, it's a lot better :) So I took another few days to test it and play with it :)

As for ScAIEdit 3.1 progress, I've worked on it yesterday, and it's advancing well. I've gathered all expected changes in a TO-DO file, and I'm progressing on the list :) It shouldn't be too long before I release ScAIEdit 3.1, unless something unexpected happens again ;) Please be patient, you won't regret it! :)

{{begin-newsitem |time=2000-07-12T03:08:51Z |title=The Gold Dragon reveals some informations... |author=Gold Dragon |site=Camsys |categories=Camsys}}
After a successful launch and appreciation from many people(thanks again :), ScAIEdit III is finally available to everyone. Unfortunately, some bugs have been found and I've been working hard to solve most of them, as only few are remaining now. One day after the release, I announced in the feedbacks there would be an update called ScAIEdit 3.01 very soon, fixing all reported bugs. Time has passed, and I didn't show any visible activity sign. What happened?

First of all, I took a little break of 2-3 days after the release to relax. I played Diablo 2 during that time ;) I guess it was a good time to take it, as I spent most of my computer time these last weeks to program ScAIEdit III, and I wanted to explore D2. This done(I've not finished D2, but played enough to be satisfied ;), this doesn't complete the time of my "public short inactivity". So what happened?

What if I told you that the "set_gencmd" command that must be put after "build" commands wasn't used for that purpose? That instead, the "set_gencmd" represented the build priority, and that it also applies to "upgrade" and "tech" commands? That the headers used in the beginning of scripts are clear and meaningful? That I now understand many problems that could have occured when making scripts? That there is no "unk[0xXX]" commands in the Developer Version I'm working on?

Nothing of what I said above is false. How am I able to reveal this? Recently, my friend -=|Artanis|=- told me he has been able to establish an internal contact with Blizzard, and sent me the contact information to this source. Thanks to him, I've been able to have a very interesting talk by e-mail with this source, and Blizzard was kind enough to provide me an unofficial list of the opcode names they've used to make their scripts. Thanks to this source and Blizzard for that really nice action :)

What does it means concretely? I've been able to assign the correct names to all of my defined opcodes, and even on some undefined ones! I still have to decipher these opcodes, but with a correct name assigned to them, this helps a lot :) It will take some time to find the definition of the undefined opcodes, because there is almost 20 commands that are never used in Blizzard scripts, but that can be used in the scripts. So I still have a lot of work to do :)

I'm sure many of you would want to see this list immediately, but please be patient. The list itself will be kept private for now, to avoid any big troubles with persons complaining they don't know what to do with it, any messes with unauthorized distributions of "opcode.dat" files, or anything related. I will keep you informed of the new commands I decipher, and you will get the same commands contained in the opcode names list on the next ScAIEdit III update. You just have to be patient, okay? :) This will actually be worth it, and the AI Script Tournament will just be even more interesting. **DO NOT** ask Blizzard about this. As written above, this is an unofficial and unsupported list, so for any questions on this, please direct them to my [e-mail](mailto:GoldDragon@camsys.org). Thanks in advance.

So the ScAIEdit 3.01 update is aborted, to leave place to the ScAIEdit 3.10 update. Expect many changes to come :) Just knowing that you won't deal with unk[0xXX] opcodes and "set_gencmd" anymore should make you happy, right? ;) I'll keep you informed!

It's a really fortunate turn of events :) I hope it will continue that way ;) That's all for now, see you on next update!
{{end-newsitem}}
