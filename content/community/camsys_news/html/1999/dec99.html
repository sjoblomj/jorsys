StarGraft NewsKing Arthur @ 02:46 EST

I've just completed adding support for Self-Exectuing Patches (which can include SECWADs, too if you select one). This ability will be added into the next version of StarGraft, which looks like it should be done sometime tomorrow if all goes well. The Self-Executing Patches will be at least 170kb in size, which will grow depending on whether you have a SECWAD or not, and the size of the patch file itself.
SEPatches will only support the versions of SC that the creator of the patch has support for. I.e. a copy of versions.dat will be tacked onto the end of the SEPatch for use in loading the patch. However that file will only be as up to date as the version the patch creator had. In this way I suppose you could do multiple versions, which would be especially helpful for SC/BW versions, which for the most part are incompatible with each other because of the drastic # of changes involved in the EXE.

TileEdit News Update. (not a release yet though)Nossirahdrof @ 12:44 EST

Well, there's some good news and some bad news from the world of Tileset Editing. First, the bad news. I have recently figured out (although I should have caught it earlier) that there is a limit on the amount of graphics that can be put into a Tileset. I won't go into great detail about why, mostly because the explanation would be long and probably more than most people would understand. So for now, the ability to import tiles is somewhat limiting. Which brings me to my next news bit, this time the good part. I have successfully completed the Exporting and Importing abilities of TileEdit. There are still a few minor bits and pieces to work out, but essentially it works. So combining the bad news and the good news, we get the fact that Tiles can be imported to the Tileset, but once the limit is reached, that's it. So, what shall be done? Well, in the next few days I'm going to try and create some kind of Tileset optimization to take away minitiles that have doubles or flipped doubles (probably the same technique Blizzard uses to reduce file size). This should help in lowering the size of the Tileset files once you've imported new graphics. Hopefully with this, the limit will be reached only in rare circumstances, but it will always be there. So when can the next release be expected? Hopefully if all goes well, by Christmas I'll have a new version out, one way or another. If I find that the optimization will be more difficult than I am estimating, then I'll release a version without it, but hopefully, I'll get it put in so it'll be a much better release. Finally, here's a little sample of something I've extracted from the Twilight Tileset. It took me a very short time to extract and assemble the tiles into this image of the Twilight Bridge. Thursday, December 02, 1999
StarGraft ReleasedKing Arthur @ 18:53 EST

StarGraft (the secret util I promised earlier) is now available to the public. StarGraft is an EXE Editor which allows you to change unit commands, requirements for units to be built, technologies to be used/researched, and upgrades to be performed. It's really advanced and the tool is in its infancy so it's probably not terribly user friendly. You must save your changes over an existing EXE of the same version (basically make a backup of your exe and save changes to the copy). You won't be able to play Multiplayer if you make the changes - I hope to start implimenting a better patch interface than what is there now (basically nothing) so that Multiplayer is possible if you and everyone you're playing with all have the same patch. For now there is unfortunately no help file with it (because I haven't had time to write one) but it's a lot similar to WarHack - if you ever used that - and the manual for that is available on the WC Software page.

Well, Not All The News is Bad...KramerBoy @ 17:33 EST

Finally some good news to offset the problems that KA has been facing... The ICE Beta is now officially released (FINALLY!!!). Though I know that it's long overdue, and that I should have done a much better job with all the time I've had, I am glad that it's finally out. The program is about 80% completed on the basics, so I figured now is as good a time as any to give it to you guys to test.

For those of you who don't know, ICE is a program that edits iscript.bin - the file which stores the scripts that control StarCraft animations. It is very powerful in the hands of a skilled user, though only those with extensive knowledge of HEX editing have been able to truly customize it... Until now =). With the current ICE build, you can completely manipulate the headers and opcodes that the file uses, all using a very simple and effective interface. ICE Beta includes full CWAD support, which eliminates the need to import and export files that you want to edit, and makes for a very convienient editing process.... Is it just me or does this sound like a really corny commercial? =)

Make sure to download the ReadMe/Demo file. I would have added it to the installer if I had remembered. And READ THE README! It's really important that you follow the instructions it has in there, so that I can get ICE out of its Beta stages as quickly as possible.

The demo CWAD that I included is basically a brief demonstration of ICE's abilities. At first I had something much more elaborate, but after playing it a few minutes, I realized that it wasn't all that fun to use. So, instead, I made a MOD that can really be played. All I did was make a few changes to iscript.bin, so that none of the blood animations disappear. Ya know when a Marine dies, and it leaves that little blood mark on the ground that slowly fades? Well, now it doesn't fade. Makes for some really messy maps, and it just looks plain cool =). Also, the Siege Tank might Siege up a little strangely; I can't remember if I took that out =).

Yet another setback...King Arthur @ 11:42 EST

Well it looks like things definately are not looking too good. I thought that I had backed everything up via my Zip drive on friday but it appears that it never actually wrote any data to the disks... (yes I did use a sledge hammer on the drive - to no effect). So that means that I have lost all current source code for Arsenal III and several other projects I had been working on, most of which were unannounced. Fortunately I did make backups of my source on the 16th of November, so the source exists from then for all the tools. However that source is so old (now) that it doesn't include the War2 Upgrade Editor in Arsenal III or for that matter the Tileset Editor or the Graphic Editor that I had been working on and was hoping to release at the end of last week.
I did get my new HD today - and lucked out there. The new one is 27.3 gig, which is 11 gig larger than my old one. I guess I can't be completely upset :P Now I just have to go through the incredibly boring process of reinstalling everything. Ugh.
So in any case what does this mean for the future of Arsenal III? The prognosis is not good. I really don't want to redo the War2 Upgrade Editor or the Tileset Editor. I'd like to keep working on the latter, but without my old source that's impossible. So it looks like "that's all folks" for Arsenal III. Don't bother to email me and plead with me to keep going because I've had it.
I think that unless I can find a new and stimulating project soon, this looks like the end for me...
